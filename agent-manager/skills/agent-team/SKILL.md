# 多智能体协作

目标：盘点 → 任务契约 → 分批派发 → 验证 → 汇总。调度者负责依赖、冲突和最终验收，也可完成未派发的独立工作。不要重复执行正在进行的子任务。

## 1. 确认可用能力

- 以当前会话的可用 agent types 和工具为准，磁盘定义不代表当前会话已经加载。
- 按 description 和工具权限选人；只读 agent 不承担写入任务。
- 只有运行时确实提供 general-purpose 时才可选它作为兜底。
- 若没有可用的派发工具或合适 agent，明确说明限制，由主会话执行或解释阻塞原因，不伪造工具调用或创建结果。
- 任务目标不明确且影响关键决策时询问用户；常规实现选择由调度者决定。

## 2. 建立任务契约

为每个子任务填写以下字段，并在主会话维护任务表：

| 字段 | 内容 |
| --- | --- |
| ID | 唯一标识，如 T1 |
| 目标 | 可单独验收的结果 |
| 依赖 | 前置任务 ID；没有则填无 |
| 上下文 | 工作目录、相关文件、已知结论 |
| 读写范围 | 只读，或明确允许修改的文件/目录 |
| 验收 | 应满足的行为、检查命令和预期结果 |
| 交付 | 变更文件、结果证据、风险及阻塞 |
| 状态 | 待执行 / 运行中 / 完成 / 失败 / 阻塞 / 取消 |

派发前检查依赖不存在环或缺失 ID。先处理前置任务；强耦合任务合并执行，不为并行而拆分。

## 3. 分批派发与写入归属

- 独立且依赖已验收的任务，在同一条消息的多个 Agent 调用中并行派发；遵守运行时并发上限，不假设固定容量。
- 同一文件同时只能有一个写入者。共享配置、锁文件和公共接口指定一个集成负责人，其余 agent 提供建议或补丁。
- 目录范围有重叠也视为冲突，先收窄范围或改为串行。若使用独立工作树，仍需指定最终集成顺序。
- 派发时附上完整任务契约。子 agent 不得扩大写入范围、覆盖用户已有改动或自行执行发布、合并、删除等未获授权操作。
- 上游运行中或仅口头声称完成时，不启动依赖其结果的下游写入任务。

## 4. 等待与失败恢复

- 记录运行时返回的任务标识；仅使用当前工具实际支持的等待、消息或取消功能。
- 未收到完成结果，不推测成功；未回复不等于失败，也不盲目创建重复写入任务。
- 失败时记录原因、已修改文件和剩余工作。确认旧任务停止或释放写入范围后，才可接管或重新派发。
- 对临时错误可做一次有明确理由的重试；重复失败则标记阻塞并报告，不无限重试。
- 用户改变目标或取消时，停止派发后续任务；支持取消时取消相关任务，并如实列出已经发生的改动。

## 5. 验收与汇总

要求子 agent 使用以下格式交付：

```text
任务 ID / 状态：
结论：
变更文件或定位依据：
验证：命令、结果；未执行时说明原因
风险与未完成事项：
```

调度者核对实际 diff 和必要检查结果，避免将“agent 已回复”直接等同于“验收通过”。相关测试在集成后执行；没有运行测试就明确写未运行。发现冲突时由集成负责人处理，不采用最后写入覆盖。

最终面向用户说明：完成了什么、关键文件、验证证据、失败或阻塞项和剩余工作。合并重复结论，保留分歧；仅在所有必要任务完成并验收后宣称整体完成。
